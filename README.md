# nki-gpt2-block

A GPT-2 decoder block written as hand-tiled [NKI](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/nki/index.html) kernels for AWS Trainium, checked against PyTorch on real GPT-2 weights.

NKI (Neuron Kernel Interface) is the low-level language for programming a Trainium NeuronCore directly: you place tiles in on-chip memory and issue instructions to the Tensor, Vector, Scalar and GpSimd engines. This repo is a small model-enablement exercise in that language: take an open-weight model, write the kernels its block needs, and show the numbers match.

**No Trainium hardware was used.** Everything runs on two simulators, and there are no latency or throughput numbers here. See [What is and is not verified](#what-is-and-is-not-verified).

## Results

All 12 GPT-2 (124M) blocks running on these kernels, compared with the float32 PyTorch model over a 205-token prompt. The compiled-backend column executes the instructions `neuronx-cc` emitted for Trainium2.

| run | top-1 next-token agreement (Python simulator) | top-1 agreement (compiled by `neuronx-cc`) | mean KL (Python simulator) |
|---|---|---|---|
| NKI kernels, float32 | 205/205 | 205/205 | 7.8e-10 |
| NKI kernels, bfloat16 | 204/205 | 203/205 | 2.2e-04 |
| PyTorch CPU bfloat16 (baseline) | 203/205 | 203/205 | 2.6e-04 |

- In float32 the kernels reproduce the model: the largest logit difference is 2e-4 on logits of magnitude ~200.
- In bfloat16 the kernels lose as much as PyTorch's own bfloat16 does, which says the loss comes from the data type and not from the kernels.
- Every kernel compiles to a NEFF (the binary a Trainium device loads) for both Trainium2 and Trainium3, in float32 and bfloat16, at full GPT-2 shapes.

Full tables: [`results/accuracy.md`](results/accuracy.md), [`results/accuracy_neuronx_cc.md`](results/accuracy_neuronx_cc.md), [`results/compile_report.md`](results/compile_report.md).

## The kernels

| kernel | file | what it does |
|---|---|---|
| `linear_T`, `linear_gelu_T` | [`kernels/linear.py`](src/nki_gpt2_block/kernels/linear.py) | Tiled matmul with the bias add, optional GELU, PSUM eviction and dtype cast fused into one instruction |
| `mlp_T` | [`kernels/linear.py`](src/nki_gpt2_block/kernels/linear.py) | `fc -> GELU -> proj` as one kernel; the 4x-wide hidden activation never leaves SBUF |
| `layernorm_T` | [`kernels/norm.py`](src/nki_gpt2_block/kernels/norm.py) | Mean and variance in five instructions per token tile, then a layout change with the affine fused in |
| `causal_attention_T` | [`kernels/attention.py`](src/nki_gpt2_block/kernels/attention.py) | Multi-head causal attention: scores, on-the-fly causal mask, stable softmax, context |
| `residual_add_T` | [`kernels/residual.py`](src/nki_gpt2_block/kernels/residual.py) | Residual add that reads the transposed branch straight from PSUM |

[`block.py`](src/nki_gpt2_block/block.py) chains them into one block, and [`gpt2.py`](src/nki_gpt2_block/gpt2.py) drops that block into the real model.

## Design notes

The hardware rules that shape everything: on-chip tiles have at most 128 partitions (dim 0); `nc_matmul` computes `stationary.T @ moving` and contracts along the partition dimension; reductions only work along free dimensions; per-partition `[128, 1]` vectors can be applied for free by several instructions.

**1. Two layouts, chosen per kernel.** A linear layer wants *features on partitions* (feature-major, `[D, T]`), because then the contraction is on the partition dimension with no transpose, and the output bias is a per-partition vector that `nisa.activation` adds while it evicts PSUM. LayerNorm and softmax want *tokens on partitions* (token-major, `[T, D]`), because they reduce over features or keys, and only free dimensions can be reduced. The residual stream is kept token-major and the branches feature-major, with the layout changes done by Tensor Engine transposes inside `layernorm_T` and `residual_add_T`.

**2. Layout changes pay for themselves.** After `layernorm_T` transposes to feature-major, `gamma` and `beta` are per-partition vectors, so the `tensor_scalar` that evicts PSUM applies `* gamma + beta` in the same instruction. In `residual_add_T` the add reads the transposed tile directly from PSUM, so the add is the eviction.

**3. Attention has a layout conflict that cannot be designed away.** Softmax needs keys on the free dimension; the `P @ V` matmul needs keys on partitions. The kernel computes scores with queries on partitions (no transposes, since `qT` and `kT` arrive feature-major), runs softmax there, then transposes `P` in 128-key tiles for the second matmul. Causality is used twice: the mask is generated by `affine_select` with no mask tensor, and key tiles that lie entirely in the future of a query tile are never scored or multiplied.

**4. LayerNorm without a centered tile.** `activation(square, bias=-mean)` computes `(x - mean)^2` and accumulates its row sum in one instruction, and the final `tensor_scalar(+ -mean, * rstd)` normalizes from the original tile. Variance is still computed from centered values, so a large mean does not cost precision (there is a test for a mean of 300).

## What the compiler says

`scripts/compile_report.py` compiles each kernel at GPT-2 shapes (128 tokens) and records the instruction counts `neuronx-cc` prints. These are counts, not time.

| observation (Trainium2) | float32 | bfloat16 |
|---|---|---|
| `MATMUL` instructions for the QKV projection (108 `nc_matmul` calls) | 216 | 108 |
| All instructions, `mlp_T` (fused) | 1607 | 1010 |
| All instructions, the same MLP as two separate kernels | 1672 | 1096 |

- **bfloat16 halves the Tensor Engine work.** Each float32 `nc_matmul` call is emitted as two `MATMUL` instructions; each bfloat16 call as one.
- **Fusing the MLP saves 4-8% of instructions**, from not storing and reloading the hidden activation through HBM. The saving is small because streaming the weight tiles dominates the instruction count.

## What the accuracy tables show

- NKI bfloat16 error is at or below PyTorch's bfloat16 error at every stage of blocks 0, 5 and 11. The kernels accumulate and compute statistics in float32 and round once, at the output of each kernel.
- In block 11 the bfloat16 residual stream is off by about 3% of its largest value, in PyTorch as well. The hidden state entering that block peaks near 3000 and the block's output near 380, because the branches cancel the large components. Input rounding that is small relative to the input is therefore large relative to the output. This is a property of GPT-2 in bfloat16, not of the kernels.

## What is and is not verified

Verified here:

- **Numerics** against PyTorch for every kernel (float32 and bfloat16; partial tiles; sequences longer than one tile), for a full block, and for all 12 blocks on real weights. The PyTorch reference itself is checked against the `transformers` implementation.
- **Compilation** by `neuronx-cc` 2.28 to a NEFF for `trn2` and `trn3`, including SBUF and PSUM allocation at full GPT-2 shapes, and execution of the compiled instructions on the compiler's simulator with results matching the Python simulator.

Not verified:

- **Nothing ran on a Trainium device.** Simulators can differ from hardware; the NKI docs list known gaps, and the Python simulator is marked experimental.
- **No performance numbers.** These kernels have not been compared with the NKI Library's production kernels, which are tuned on real hardware.
- The compiled-backend path uses an internal NKI entry point (`StandaloneKernel(_enable_simulation=True)`), so it may break on other NKI versions. The kernels and the Python-simulator path use only public API.

## Limits and next steps

- `causal_attention_T` supports at most 512 tokens, because one query tile's scores live in a single PSUM tile. GPT-2's full 1024-token context needs a running max and sum across key blocks (FlashAttention-style online softmax).
- Feature sizes must be multiples of 128. Batch size is 1.
- Each head uses 64 of the Tensor Engine's 128 rows. Row tiling could run two heads at once.
- Kernels hand tensors to each other through HBM. Fusing the block into one kernel would remove those round trips.
- No KV cache, so this is a prefill-style forward pass, not token-by-token decoding.
- Run on a Trainium instance and profile with Neuron Explorer, which is the only way to learn which of the above matters.

## Running it

Requires Linux x86_64 (or WSL2) and Python 3.12 or 3.13. The `nki` package is published on the Neuron package index.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt --extra-index-url https://pip.repos.neuron.amazonaws.com
pytest                              # kernel, block and loader tests on the Python simulator
```

Real GPT-2 weights (about 550 MB) and the accuracy report:

```bash
python scripts/download_gpt2.py
pytest -m gpt2
python scripts/run_accuracy.py      # writes results/accuracy.md
```

Optional, with the real compiler (about 600 MB):

```bash
pip install neuronx-cc --extra-index-url https://pip.repos.neuron.amazonaws.com
pytest -m neuronxcc                                  # every kernel, trn2 and trn3, both dtypes
python scripts/compile_report.py                     # writes results/compile_report.md
python scripts/run_accuracy.py --backend neuronx-cc  # about 10 minutes
```

Calling a kernel directly:

```python
import numpy as np
from nki_gpt2_block import sim
from nki_gpt2_block.kernels import causal_attention_T

qkvT = np.random.randn(3 * 768, 200).astype(np.float32)  # [3*D, T], feature-major
out = sim.run(causal_attention_T(n_heads=12), qkvT)  # [D, T]
```
